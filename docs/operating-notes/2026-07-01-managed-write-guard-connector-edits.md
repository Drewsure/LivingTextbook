# Managed Write Guard Connector Workflow

Date: 2026-07-01

## Observed Behavior

During the Living Textbook build, local `apply_patch` edits from the managed Codex session were rejected by the workspace write guard even though the repository is writable from the user's PowerShell terminal.

The user's terminal can successfully run `git pull`, `npm run typecheck`, `npm run build`, and `npm run dev` from:

```powershell
D:\LIVING TEXTBOOOK PROJECT\LivingTextbook
```

## Safe Workaround

When local patch writes are blocked:

1. Use the GitHub connector to create or update files directly on `legacy-source-import`.
2. Keep connector commits small and named.
3. Ask the user to run the standard sync/build sequence locally.
4. Treat local verification as incomplete until the user confirms typecheck/build/browser checks.

## Standard Human-Side Sync

```powershell
cd "D:\LIVING TEXTBOOOK PROJECT\LivingTextbook"
git restore apps/web/next-env.d.ts
git pull --ff-only
npm run typecheck --workspace @living-textbook/web
npm run build --workspace @living-textbook/web
npm run dev --workspace @living-textbook/web -- --hostname 127.0.0.1 --port 3000
```

## Notes

`apps/web/next-env.d.ts` is generated by Next type generation and may appear modified after `next typegen`, `typecheck`, or `build`. Restoring it before pulling prevents a harmless generated-file conflict.
