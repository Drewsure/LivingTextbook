# Local Sync And Verification Runbook

Use this when the connector has pushed new branch changes and the local Windows checkout needs to catch up.

## Standard Sync

```powershell
cd "D:\LIVING TEXTBOOOK PROJECT\LivingTextbook"
git restore apps/web/next-env.d.ts
git pull --ff-only
npm run verify:foundation
npm run dev --workspace @living-textbook/web -- --hostname 127.0.0.1 --port 3000
```

`npm run verify:foundation` now runs taxonomy coverage, game-mode coverage, package readiness coverage, web typecheck, production build, and active route checks.

## If Port 3000 Is Busy

Check whether a dev server is already running. If the site loads, do not start another server.

Open:

- `http://127.0.0.1:3000/`

If the terminal reports a specific PID to stop, stop that PID, then restart the dev server.

```powershell
taskkill /PID <PID_FROM_TERMINAL> /F
npm run dev --workspace @living-textbook/web -- --hostname 127.0.0.1 --port 3000
```

If no PID is visible and 3000 still acts stuck, use port 3002 for the session:

```powershell
npm run dev --workspace @living-textbook/web -- --hostname 127.0.0.1 --port 3002
```

Then use URLs with `http://127.0.0.1:3002/`.

## If Pull Is Blocked By next-env.d.ts

`apps/web/next-env.d.ts` is generated by Next.js. It can change locally after typecheck/build/dev.

Use:

```powershell
git restore apps/web/next-env.d.ts
git pull --ff-only
```

Do not manually edit this file.

## If Build Mentions Turbopack CSS/Internal Error

The project build script intentionally uses Webpack:

```powershell
npm run build --workspace @living-textbook/web
```

The expected build banner is:

```text
Next.js 16.x.x (webpack)
```

If the terminal shows Turbopack during production build, pull the latest branch and confirm `apps/web/package.json` still has:

```json
"build": "next build --webpack"
```
